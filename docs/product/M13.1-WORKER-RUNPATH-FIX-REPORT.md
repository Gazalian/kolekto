## Root cause

The notification worker had no runnable production artifact:

1. **Wrong entrypoint path.** `apps/worker` `tsc` output lands at `dist/src/index.js` (because `rootDir: "."` with sources under `src/`), but `start` was `node dist/index.js` → `MODULE_NOT_FOUND`.
2. **Workspace deps are raw TypeScript at runtime.** The shared packages (`@kolekto/config`, `@kolekto/db`, `@kolekto/domain`) set `emitDeclarationOnly: true` and expose `exports["."] = "./src/index.ts"`. They deliberately emit only `.d.ts` and are **transpiled at the point of use** (Next.js `transpilePackages` for the web app). They *cannot* emit JS via `tsc` because they import with `.ts` extensions (`allowImportingTsExtensions`). So the worker's `tsc`-emitted JS kept bare `@kolekto/*` imports that resolve to `.ts` sources, which plain Node cannot load → `ERR_UNKNOWN_FILE_EXTENSION`.

The worker is the only standalone Node process in the repo and had no transpile-at-use step — that was the gap. M13.1 is the first milestone to actually run it, so the gap surfaced now.

## Files inspected (read-only)

`apps/worker/package.json`, `apps/worker/tsconfig.json`, `apps/worker/src/index.ts`, `apps/worker/src/notification-processor.ts`, `packages/config/package.json`, `packages/config/tsconfig.json`, `packages/db/package.json`, `packages/db/tsconfig.json`, root `package.json`, root `tsconfig.json`, `apps/web/next.config.ts`. (`turbo.json` and `pnpm-workspace.yaml` do not exist — the repo uses **npm workspaces** with TypeScript project references; there is no bundler convention, and `esbuild@0.21.5` was already present transitively.)

## Chosen contract

The smallest fix consistent with the repo's "transpile TS at the point of use" convention is to **bundle the worker at build time** with esbuild (the web app already transpiles the same packages at build time). This touches only `apps/worker`; shared packages and their `exports` are unchanged, so the web app is unaffected.

| Question | Answer |
|---|---|
| Build command | `npm run build --workspace apps/worker` |
| Start command (prod) | `npm run start --workspace apps/worker` (= `node dist/index.js`); requires `SUPABASE_DB_URL` |
| Entrypoint emitted | `apps/worker/dist/index.js` (self-contained bundle) |
| Workspace dep resolution | Inlined **at build time** by esbuild from TS source; nothing resolves to `.ts` at runtime; no `tsx` |
| Pre-compile packages? | No — esbuild reads their TS source directly |
| Package exports → compiled JS? | No — left at `src/*.ts`; web app unchanged |
| Monorepo convention followed? | Yes — transpile-at-point-of-use (Next for web, esbuild-bundle for the worker) |

## Files changed

- **`apps/worker/package.json`**
  - `build`: `tsc --build` → `esbuild src/index.ts --bundle --platform=node --format=esm --target=node22 --outfile=dist/index.js`
  - `start`: unchanged (`node dist/index.js`) — now correct, because the bundle lands there
  - added `devDependencies: { "esbuild": "^0.21.5" }`
- **`apps/worker/tsconfig.json`**: `"noEmit": false` → `"emitDeclarationOnly": true` — `tsc --build` now type-checks and emits only `.d.ts`, so it no longer produces the misleading `dist/src/*.js` (consistent with the `config`/`db` packages).
- **`package-lock.json`**: 3 lines recording the esbuild devDependency (esbuild was already in the tree; nothing downloaded/new).

No other files changed. `apps/worker/src/*` (notification logic) was **not** modified in this task.
