## 13. Remaining notification pipeline coverage gaps

1. **No end-to-end test (Not tested).** Nothing runs audit trigger → pgmq queue → processor → delivery row →
   sender → Mailpit. The processor tests stop at delivery rows; every sender test, including D1–E9, inserts its
   event and delivery rows directly. Do not read Phase 5 as "the notification pipeline works".
2. **Switch ON → `runSenderTick` drains (Not tested).** The pause-switch path is never exercised with the switch
   on against a database (R11′), by design, since the switch is never written.
3. **Multi-attempt retry (Not tested).** Attempts 2–3, backoff growth and terminal `dead` after max attempts
   are not covered against real SMTP.
4. **Ambiguous SMTP failure (Not tested).** Connection drop after DATA (`ambiguous: true`) has no integration test.
5. **SMTP rejection paths (Not tested).** Mailpit accepts everything; 4xx/5xx SMTP replies, permanent failures
   and suppression-on-bounce are not exercised against a real server.
6. **Only two event types reach SMTP** (`member.create`, `officer_invitation.accept`). Other templates are
   unit-tested only.
7. **Real provider (Blocked by design).** The SES/production adapter is never exercised; Mailpit proves the
   SMTP path and the Message-ID contract only.
8. **Deferral outcomes (carried over).** L2/L4/L5 deferrals are integration-tested at reservation level; the
   sender mapping is unit-tested.
9. **Budget.** 21 transactional grants per full run; the stack is at 131 of 180 (refusal above 140) for the next
   24 h. Repeated full runs need waiting or `itest:reset` (separate approval).
10. **Residue.** Run-tagged rows and 9 Mailpit messages remain on the test stack, by design.
11. **Concurrency.** Parallel lanes and live mutex contention remain untested.
12. **Lexical guards are guards, not a boundary** (unchanged).
