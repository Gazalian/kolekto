## 3. Final approved architecture

**Layers.** (A) run-unique ownership of every row and address; (C) rollback for anything that needs no commit;
(D) one database mutex plus a serialised integration lane; (E) no protection bypasses, no switch writes, no
inbox wipes; (F) a dedicated, disposable second Supabase stack with its own Mailpit.
Layer (B) of the plan (scoped claim in `SenderOptions`) is **dropped** (Q5).

**Test classes.**

| Class | Definition | Runs where |
|---|---|---|
| U | no DB, no SMTP | anywhere, parallel (`npm test`) |
| R | all writes inside one rolled-back transaction (savepoints for expected errors); no SMTP | test stack only, integration lane |
| C | commits rows; may send SMTP to the test stack's Mailpit | test stack only, integration lane, under the mutex |

**Stack.** `project_id = kolekto-itest`, its own work directory with no `.temp`, ports 55420–55429 (outside
54320–54329 and outside the Windows-excluded ranges 49695–50259, 51649–51748, 57245–57844 [V]), own Mailpit
(web/API 55424, SMTP 55425), own volumes and network named by project id [V: dev equivalents are
`supabase_db_kolekto`, `supabase_network_kolekto`, label `com.supabase.cli.project`]. Same CLI `2.109.1`, so
the same Postgres image `17.6.1.166` and Mailpit `v1.30.2` [V].

**Identity and credentials.** A login role that exists only on the test stack, with a random password, plus a
random stack ID stored in the database (`alter database … set kolekto.itest_stack`) and in the git-ignored
`.env.itest`. The `kolekto.itest` flag is not used as a safety check on its own.

**Isolation of effects.**
- Every id is `randomUUID()`; short run tag only in slugs, event keys and addresses.
- Fillers (rate-limit rows) only inside rollback; never committed.
- No deletes of ledger, events, deliveries, communities, users, terms or `auth.users`. Per-test **quarantine**
  (UPDATE own non-terminal deliveries to `dead / itest_quarantined`).
- Real default claim path (`claimNextDelivery`); no production-source change.
- L5 pacing by polling the server clock, not by deleting ledger rows.
- Mailpit: assert by run-unique recipient and exact Message-ID, exact counts, no delete-all, no `inbox.total`.
- **Pause switch stays `false`** (§8).

- **Approvable?** **Yes, as narrowed.**

### R4 — Test-only role and stack identity token instead of an `'on'` marker
