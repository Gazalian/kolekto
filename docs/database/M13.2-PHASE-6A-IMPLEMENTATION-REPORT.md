## 2. Queue isolation design

The trigger enqueues into pgmq `notification_events`; pgmq reads are global, like the delivery claim. A test that
commits a domain action leaves a real message that another file or a worker could pick up. The design keeps the
queue empty between tests and lets a test touch only its own message.

| Point | Mechanism | Where |
|---|---|---|
| File start | `runPreflight` refuses when any message exists (`PREFLIGHT_QUEUE_NOT_EMPTY`), in addition to the existing read-message check (`PREFLIGHT_QUEUE_CONSUMED`) | `itest-isolation.ts` → `readQueueState` |
| Before every test | `checkpoint()` refuses unless the queue holds 0 queued and 0 read messages (`ISOLATION_FOREIGN_QUEUE`, `PREFLIGHT_QUEUE_CONSUMED`) | `assertQueueEmpty(…, "checkpoint")` |
| Per test | `harness.testOwner` owns only communities tracked since the last `checkpoint()` and issued by this run's scope | `createFileHarness` |
| Selecting the message | `waitForOwnQueueMessage` — bounded poll (10 s, 100 ms) for exactly one message whose `community_id` is the test's community; refuses on 2+ (`QUEUE_MESSAGE_AMBIGUOUS`) or timeout (`QUEUE_MESSAGE_TIMEOUT`); never a fixed sleep | `itest-queue.ts` |
| Acknowledgement | `archiveOwnQueueMessage` → `pgmq.archive` (Q6-1): the row moves to `pgmq.a_notification_events` as evidence; no deletion | `itest-queue.ts` |
| afterEach | `harness.recoverOwnQueue()` archives, through the same guarded path, any message left for the **current test's** communities; errors are recorded and reported by the next `checkpoint()` / `finish()` (`QUEUE_RECOVERY_FAILED`) | `itest-isolation.ts` |
| File end | `finish()` reports any queued or read message (`QUEUE_RESIDUE`) and still releases the mutex | `assertQueueEmpty(…, "finish")` |

There is no queue-wide delete, purge, pop, read, `set_vt` or drop anywhere, and no way to archive by bare
`msg_id`. Every query reading the queue is a constant or placeholder-built `select` with bound parameters.

These checks apply to **all seven** integration files (stricter than before for the six existing files; they
never enqueue committed messages, so no behaviour change is expected — Inferred, not executed).

## 3. Ownership and archive protections

### 3.1 Runtime checks (`archiveOwnQueueMessage`)

A message is archived only when **all** hold, else nothing is written:

1. **Issued handle for this owner.** `message` must be the exact frozen object that `findOwnQueueMessages` /
   `waitForOwnQueueMessage` returned for the same `owner` object (a `WeakMap` records the issuing owner). A
   hand-built object, a spread copy, or a handle read for another owner (another test, file or run) is refused
   before any query (`QUEUE_MESSAGE_NOT_OWNED`).
2. **Owner still owns the community.** `owner.owns(communityId)` is re-evaluated at archive time. The harness
   owner stops owning a community when the next test's `checkpoint()` runs, so a handle from an earlier test
   cannot be archived later.
3. **Database re-check, locked.** In one transaction:
   `select msg_id … from pgmq.q_notification_events where msg_id = $1::bigint and message ->> 'community_id' = $2 for update`
   must return exactly that row; otherwise the transaction rolls back and no archive statement is issued.
4. **Exactly one archived row.** `select pgmq.archive('notification_events', $1::bigint) as archived` must return
   one row with `archived = true`; otherwise `QUEUE_ARCHIVE_FAILED` and rollback.

Reads are restricted the same way: every community id passed to a queue read must be a lowercase UUID owned by the
owner, no duplicates, at most 50; and any row the database returns for another community is refused.

### 3.2 Lexical guard (`itest-acceptance.ts`)

- **New rule, whole test tree:** any call `pgmq.<send|send_batch|archive|delete|pop|read|read_with_poll|set_vt|purge_queue|drop_queue|create*|detach_archive|convert_archive_partitioned>(`
  and any `delete from` / `insert into` / `update` / `truncate` on `pgmq.*` is a violation. Previously there was no
  pgmq rule at all, so this strengthens the guard.
- **One exception:** `support/itest-queue.ts` may hold exactly one pgmq call, it must be the literal
  `select pgmq.archive('notification_events', $1::bigint) as archived` (archive only, the one queue, one bound id),
  and it must be preceded in the same function by `assertOwnedQueueMessage(owner, message);`. A second call, a
  different function, a different queue, an array of ids, a missing or misplaced assertion all keep the violation
  (unit-tested).
- No existing rule was removed or relaxed. The ledger-filler and `set_config` exceptions are unchanged.

### 3.3 Known violation recorded

`test/dead-letter.test.ts` (pre-existing, untracked, not modified) contains a copy of the `index.ts` event loop with
`pgmq.archive` and `pgmq.delete` calls run only against a recording fake connection. The new rule reports it (2
findings). It is recorded in `KNOWN_VIOLATIONS` with that explanation, not exempted; the frozen-map test fails if it
changes.
