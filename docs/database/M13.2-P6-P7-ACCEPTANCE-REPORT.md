## 2. P6 Implementation Review

### Code inspection

`dead-letter.ts` defines:
- `MAX_READ_CT = 5` — the poison threshold.
- `shouldDeadLetter(readCt)` — returns true when `readCt > MAX_READ_CT`.

`index.ts` event loop integration:
- Checks `shouldDeadLetter(msg.read_ct)` before processing each message.
- Poison messages are archived via `pgmq.archive('notification_events', msg_id::bigint)`.
- Archive failures are isolated in a `try/catch` — a failed archive does not crash the loop.
- Healthy messages continue processing in the same batch.
- Normal message deletion (`pgmq.delete`) remains intact.
- The `continue` keyword ensures the loop proceeds to the next message after archival.

## 4. P7 Template Architecture

### Supported events

| Event | Template function | Subject pattern |
|---|---|---|
| `member.create` | `renderMembershipConfirmation` (verb: "added to") | "You have been added to {community}" |
| `member.approve_join` | `renderMembershipConfirmation` (verb: "approved to join") | "You have been approved to join {community}" |
| `officer_invitation.accept` | `renderOfficerAppointment` | "You are now a/an {role} of {community}" |
| `officer_term.end` | `renderOfficerTermEnd` | "Your {role} term in {community} has ended" |

### Design

- Pure functions: no database, no clock, no side effects.
- `escapeHtml()` covers the 5 dangerous characters: `& < > " '`.
- `str()` reads payload values with type checking; returns empty string for non-strings.
- `article()` returns only "a" or "an" (never user-controlled).
- `emailLayout()` wraps body in a responsive HTML email table structure.
- Fallback: `buildTemplatedMessage` delegates to `buildPlaceholderMessage` for unknown events.
- `buildEmailMessage` is the single entry point used by the sender.

## 5. HTML Escaping and Security Findings

### Escaping coverage

Every user-controlled value inserted into HTML is escaped:
- `communityName` → `escapeHtml(communityName)` in all templates
- `memberCode` → `escapeHtml(memberCode)` when present
- `role` → `escapeHtml(role)` in officer templates
- `verb` → `escapeHtml(verb)` (hardcoded values, escaped defensively)
- `article(role)` → `escapeHtml(article(role))` in HTML context
- `title` → `escapeHtml(title)` in `<title>` element

### Adversarial inputs tested (all pass)

| Payload | Verified |
|---|---|
| `<script>alert(1)</script>` | Escaped to `&lt;script&gt;` in HTML; literal in plain text |
| `<img src=x onerror=alert(1)>` | Escaped to `&lt;img` in HTML |
| `"'><svg onload=alert(1)>` | `&quot;`, `&#39;`, `&lt;svg` all escaped |
| HTML in member_code (`<b>BOLD</b>`) | Escaped to `&lt;b&gt;` |
| Quotes and apostrophes (`O'Brien's "Club"`) | `&#39;` and `&quot;` in HTML; preserved in text |
| Newlines in community name | Present in output, no structural break |
| 500-character community name | Renders without error |
| 200-character officer role | Renders without error |
| Empty payload | Fallback values used ("your community", "officer") |

### Subject line safety

Subject lines contain unescaped user-controlled values (correct for email headers, not HTML).
The adapter's `assertValidEmailRequest` rejects control characters (CR, LF, C0, DEL, U+2028,
U+2029) via `hasForbiddenHeaderChar()`, blocking header injection. Subject length capped at 200 chars.

### No unsafe HTML contexts

No user-controlled value is inserted into:
- `href` or `src` attributes
- `style` attribute values
- JavaScript contexts
- Event handler attributes
