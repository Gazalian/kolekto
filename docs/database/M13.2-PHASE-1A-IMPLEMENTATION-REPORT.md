## 3. Integration gate architecture

```
npm run test:integration
  └─ node --experimental-strip-types test/support/run-integration.ts
       └─ runIntegrationLane()                       (itest-lane.ts)
            1. parseIntegrationEnvironment(env)       static, no I/O          → refuse = exit 1
            2. list test/integration/**/*.test.ts     ≥ 1 file, each gated,
                                                      no pause-switch write    → refuse = exit 1
            3. spawn node --test --test-concurrency=1 --test-reporter=tap <files>
               child env: KOLEKTO_ITEST_REQUIRED=1; SUPABASE_DB_URL, DATABASE_URL,
               SUPABASE_SERVICE_ROLE_KEY, KOLEKTO_WORKER_INTEGRATION, MAILPIT_API
               and every EMAIL_* variable removed (case-insensitive)
                 └─ each file: before(() => gate.verify())   (itest-gate.ts)
                      a. KOLEKTO_ITEST_REQUIRED === "1"
                      b. parseIntegrationEnvironment(env)
                      c. identity probe (read-only, bounded)  → verifyLiveIdentity
                      d. pause-switch read (read-only, bounded) → exactly one row, === false
                      e. register the config object in a module-private WeakSet
                    tests: gate.verified()  (throws NOT_VERIFIED unless (a)–(e) passed)
                    after(() => gate.postflight())  → pause switch still exactly false
            4. evaluateRun(): TAP summary present; tests > 0; pass == tests;
               fail = cancelled = skipped = todo = 0; no SKIP/TODO directive  → else exit 1
```

Key properties:

- **No skip path exists.** Every unmet condition is a thrown `IntegrationGateError`. Verified against real
  `node:test` 22.12 output: a refusal in `before()` reports the file's tests as `cancelled` (the suite as
  `hookFailed`) and exits non-zero; the canary also treats `cancelled` as failure.
- **Suite-level skips are caught.** Verified: `node:test` 22.12 does not count a skipped `describe()` in
  `# skipped` (`# tests 0`, `# skipped 0`). A file with one passing test and one skipped suite reports
  clean counters. The canary therefore also counts `# SKIP` / `# TODO` directives on every `ok`/`not ok`
  line (the TAP reporter escapes `#` in names as `\#`, so an unescaped directive is unambiguous).
- **Refusal is permanent per gate.** A second `verify()` rethrows the first refusal; identity checks are
  never retried.
- **Only issued environments are usable.** `verified()` returns the object registered in step (e).
  `assertVerifiedEnvironment()` accepts nothing else, including a fresh `parseIntegrationEnvironment()`
  result or a copy. Phase 1b's connection helpers must call it.
- **Probes are injected.** `probeIdentity(db)` and `readPauseSwitch(db)` are function parameters. Phase 1a
  ships the SQL they must run (`IDENTITY_PROBE_SQL`, `PAUSE_SWITCH_PROBE_SQL`, both single read-only
  `select`s) but no implementation that connects.

## 4. Environment identity design

**Variables read (no defaults, no fallback):** `KOLEKTO_ITEST_DB_URL`, `KOLEKTO_ITEST_SMTP_PORT`,
`KOLEKTO_ITEST_MAILPIT_API`, `KOLEKTO_ITEST_STACK_ID`. `SUPABASE_DB_URL`, `EMAIL_SMTP_*`, `MAILPIT_API` and
`.env.local` are never read. They are stripped from the child process.

**Static rules (all violations collected, then one refusal):**

| Area | Rule |
|---|---|
| Presence/format | Missing or empty → `ENV_MISSING`; surrounding whitespace or control characters → `ENV_MALFORMED` |
| Ambient overrides | `PGHOST`, `PGHOSTADDR`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGSERVICE`, `PGOPTIONS` set → refuse |
| DB URL | `postgresql:`/`postgres:` only; no query or fragment (they can override host/port/user); explicit port; exactly one plain-identifier database name |
| DB host | Literal `127.0.0.1` or `[::1]` only. `*.supabase.co/.com/.net/.in` → `DB_HOST_REMOTE` (staging/production); any other host, including `localhost` (resolved, not literal), private IPs and `0.0.0.0` → `DB_HOST_NOT_LOOPBACK` |
| DB credentials | User must be `kolekto_itest`. Stock Supabase roles (`postgres`, `supabase_admin`, …) or password `postgres` → `DB_DEVELOPER_CREDENTIALS`; password shorter than 16 → `DB_PASSWORD_WEAK` |
| Ports | DB, SMTP and Mailpit API each in 55420–55429, none in 54320–54329 (developer: DB 54322, Mailpit 54324, SMTP 54325), and all three distinct |
| Mailpit API | Bare `http://` origin, loopback literal, explicit port; developer port → `MAILPIT_DEVELOPER` |
| SMTP | Host fixed to `127.0.0.1`; developer port → `SMTP_DEVELOPER` |
| Stack ID | Lowercase version-4 UUID (`crypto.randomUUID()` format). `on`, `true`, nil UUID, v1, uppercase → refuse |

**Live identity (`verifyLiveIdentity`, on the probe result for the connection the tests use):** exactly one
well-formed row; `current_user` **and** `session_user` = `kolekto_itest`; `current_database()` = URL database;
`inet_server_port()` = URL port; `current_setting('kolekto.itest_stack', true)` = `KOLEKTO_ITEST_STACK_ID`.
A null or empty marker → `IDENTITY_STACK_MISSING` ("not the test stack, developer database?"). A different
value → `IDENTITY_STACK_MISMATCH` (other or stale stack). The boolean `kolekto.itest` marker is not used.

**Defence in depth:** credentials, variable names, endpoint ranges, the random stack token and the role
would all have to be wrong in the same direction at once. The strongest layer (a role that exists only on
the test stack) becomes real in Phase 3, when the bootstrap creates it.

**Secrets:** the DB URL and the stack ID are wrapped in `Secret` (`toString`/`toJSON`/`util.inspect` →
`[redacted]`; `reveal()` is the only accessor). Refusal messages are built from fixed text, variable names
and port numbers only. They never carry a `cause`, because `new URL()` errors and driver errors embed their
input. Probe errors expose only a SQLSTATE (`28P01`) or a Node errno (`ECONNREFUSED`).

## 7. Security properties

1. The developer database is refused at four independent points: developer port range, developer
   credentials, a missing stack marker on the live connection, and a stock role as `current_user`/`session_user`.
2. Hosted Supabase (staging, production) and every non-literal-loopback host are refused before any probe runs.
3. The developer Mailpit (API and SMTP) is refused, and there is no default endpoint to fall back on.
4. Integration children never inherit `SUPABASE_DB_URL`, `DATABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
   `MAILPIT_API` or any `EMAIL_*` variable (including real SES credentials). A test therefore cannot reach
   the developer stack or a real provider through ambient configuration.
5. The harness has no write capability for the pause switch. A switch found ON is reported, never
   corrected. A missing switch row is a refusal.
6. Lexical guards (runner and unit test) reject any switch write in the lane's files.
7. No secret appears in any refusal, log line or serialised configuration.
8. Every probe is bounded by a timeout (10 s default); a hang is a refusal.

## 8. Remaining limitations

1. **[U] `inet_server_port()` inside Docker.** The Supabase Postgres container probably listens on 5432
   and publishes it as the host port. If so, `inet_server_port()` reports 5432, and the port check (as the
   checklist specifies) refuses every real connection. That is the safe direction. Phase 1b/3 must confirm
   and then either compare against the container port or have the bootstrap store the host port next to the
   stack ID.
2. **The brand only protects code that asks.** `assertVerifiedEnvironment` prevents misuse only if the
   Phase 1b connection factory requires it. Phase 1b must route every connection through it.
3. **The lexical checks are guards, not a boundary.** A file could satisfy the gate-usage pattern in a
   comment. The runtime gate and the canary are the controls.
4. **Credentials are checked statically only.** Isolation by credentials becomes real only when Phase 3
   creates `kolekto_itest` on the test stack alone.
5. **Mailpit identity is not verified live.** Phase 1a validates the endpoint and makes no request. A
   read-only check that the API belongs to the test stack is still open for Phase 1b/3.
6. **Environment loading is undecided.** The lane reads `process.env` only. How `.env.itest` is loaded
   (for example `node --env-file`) is Phase 3.
7. **The existing integration files run in neither lane** until they are migrated (§5). Their switch writes
   and developer-URL headers are unchanged. The lexical guard covers only `test/support/` and
   `test/integration/`.
8. **Ambient `PG*` refusal** may refuse a developer shell that exports `PGUSER` and similar variables. The
   message names the variables.
9. **Node coupling.** The `test` script relies on extglob support in Node 22.12's internal glob, and the
   canary relies on the `node:test` TAP format. Both are pinned by unit tests that fail if behaviour changes.
   A format change in the canary fails closed (`RUN_INCONCLUSIVE`).
10. Preflight items from checklist §7.6–7.7 that need a database (foreign claimable rows, heartbeat age,
    queue consumer, L4 headroom, scope postflight) are not in Phase 1a.
